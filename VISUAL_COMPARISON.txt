GRID POSITION CALCULATION COMPARISON
================================================================================

Example: Converting pixel position 25 to grid position

BEFORE (Old Formula):
    x = 25
    _tile_index = round((25 - 8) / 16)
    _tile_index = round(17 / 16)
    _tile_index = round(1.0625)
    _tile_index = 1
    result = (1 * 16) + 8
    result = 24

    Sprite at x=25 snaps to grid position 24
    That's the WRONG grid (offset by 8)

AFTER (New Formula):
    x = 25
    result = 16 * round(25 / 16)
    result = 16 * round(1.5625)
    result = 16 * 2
    result = 32

    Sprite at x=25 snaps to grid position 32
    That's the CORRECT grid (nearest boundary)


================================================================================
COORDINATE SYSTEM UNDERSTANDING
================================================================================

GRID SYSTEM:
  Each tile is 16 pixels wide
  Tile boundaries at: 0, 16, 32, 48, 64...
  Tile centers at: 8, 24, 40, 56, 72... (old system)
                   8, 24, 40, 56, 72... (8 pixels into each tile)

SPRITE SYSTEM:
  Sprites are 32x32 pixels
  When placed at grid position X, origin determines where visually
  Old origin (8,8): Shifted sprite left
  New origin (16,16): Centered sprite

THE FIX:
  OLD: Place sprite at offset grid (8, 24, 40...) with origin (8,8)
  NEW: Place sprite at boundary grid (0, 16, 32...) with origin (16,16)

  Both achieve centered sprites, but new way is simpler!

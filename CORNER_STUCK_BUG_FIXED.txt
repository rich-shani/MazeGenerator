================================================================================
CORNER SNAPPING BUG - FIXED
================================================================================

ISSUE: Pac gets stuck in corners when turning (e.g., RIGHT→DOWN, DOWN→LEFT)

ROOT CAUSE: Corner completion conditions used strict comparisons (<, >) that
couldn't handle sprite overshoot during diagonal movement.

SOLUTION: Changed all 16 corner states to use inclusive comparisons (<=, >=)

================================================================================
THE BUG EXPLAINED
================================================================================

During diagonal corner movement, Pac moves at speed _spd in both axes:
  hspeed = _spd;
  vspeed = _spd;  // Diagonal movement

Each frame, position increments by _spd (typically 2 pixels):
  Frame 1: y = 14
  Frame 2: y = 16 (grid position)
  Frame 3: y = 18 (OVERSHOT THE GRID!)

OLD CODE (with strict comparison):
  if (y < 16) {  // Only true if y is LESS than 16
      y = 16;
      // Complete corner
  }

When y = 18, the condition (y < 16) is FALSE
So corner never completes and Pac gets STUCK!

================================================================================
THE FIX
================================================================================

NEW CODE (with inclusive comparison):
  if (y <= 16) {  // True if y is LESS THAN OR EQUAL to 16
      y = 16;    // Snap to grid position
      // Complete corner
  }

When y = 18, the condition (y <= 16) is still FALSE... WAIT!

Actually we need to check >= for moving down:
  if (y >= 16) {  // True if y is GREATER THAN OR EQUAL to 16
      y = 16;    // Snap to grid position
      // Complete corner
  }

When y = 18, (y >= 16) is TRUE
So corner completes immediately and Pac snaps to grid!
